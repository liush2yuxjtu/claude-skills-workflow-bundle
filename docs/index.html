何为「工序四章」

一套为 Claude Code 装配的 四把工序小刀,首尾相连,各司其职。 从打开 worktree,到本地 QA,到 MR 提交前的 四段自检,到 rebase + push + 开 MR,全程不脱手。

  • worktree-self-host 让每个 worktree 都有自己的端口,push 之前就位
  • worktree-qa diff → host → playwright,四相 QA 一气呵成
  • pre-mr 4 段式自检,默认就地修,不写遗留
  • submit-mr rebase + push + GitLab MR,OAuth 探活兜底

四把刀,各擅其能

展开看,每把刀的形制、发力点、收招式。

01 · 起 meta

worktree-self-host

自托管

为每个 worktree 生成端口隔离的 dev launcher:FNV-1a 派生端口、scoped pidfile 优雅停机、stack 自动嗅探(FastAPI / Next.js / Go / Rails / Rust),首次调用时用 skill-creator 现编一份。

/worktree-self-host launch this worktree per-worktree ports 
# 启动本 worktree 的 dev stack
worktree-self-host up
# → backend :7801  frontend :3501  pg :5433
02 · 验 e2e

worktree-qa

四相 QA

git diff 列举新旧特性 → 调起 worktree-self-host 拉起 dev stack → 用 playwright-cli 逐个点过 → 把 app 弹到 Chrome 让你手测签字。

/worktree-qa QA this worktree smoke test the worktree 
# 自动发现的 feature 列表
git diff main..HEAD --stat
# → 8 files, +312 -94
playwright run --features all
03 · 净 4-gate

pre-mr

四段自检

QA · e2e · diff · 视觉证据,四扇门一道一道过。默认行为是 动手修,不写 follow-up MR,撞模糊才升用户。

/pre-mr 准备 MR 开 MR 前 ship MR 
gate 1 · qa pass      ✓
gate 2 · e2e green    ✓
gate 3 · diff clean   ✓
gate 4 · evidence ok  ✓  → ready to push
04 · 行 gitlab

submit-mr

最后一公里

worktree 探测 → 委托 /pre-mr → fetch + rebase → zh-CN / 视觉证据补齐(≥ 0.30 安全垫)→ push --force-with-lease → GitLab 三段协议探活 → 创建 MR。

/submit-mr 提个 MR open the MR ship it 
probe  · https://gitlab/...  EOF ✗
        http://gitlab/...   200 ✓  (fallback)
push    · --force-with-lease
mr      · web_url  ✓  ready
肆 · 装
肆

装入 ~/.claude/skills/

一行 git clone,四个 cp,落地即用。

# 1. 拉仓库
git clone https://github.com/liush2yuxjtu/claude-skills-workflow-bundle.git
cd claude-skills-workflow-bundle

# 2. 四个技能拷进 Claude Code 的 skills 目录
cp -R worktree-self-host worktree-qa pre-mr submit-mr ~/.claude/skills/

# 3. 重启 Claude Code,4 个技能即可在合适的语境下自动触发

装完后,只要在 Claude Code 里说 /worktree-qa、/pre-mr、/submit-mr 任意一句,就会按本仓库里的 SKILL.md 跑起来。
